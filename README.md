# Планер

Персональное приложение для Windows на **.NET 10 + WinUI 3**, с архитектурой **MVVM** и локальной **SQLite**.

## Установка

Готовый установщик: `dist/Planer-1.3.0-win-x64-setup.exe`. Установка для текущего пользователя; .NET и Windows App SDK входят в сборку. Приложение добавляется в меню «Пуск», ярлык рабочего стола необязателен. При обновлении существующий ярлык рабочего стола получает новую иконку; ярлыки и окна используют единый идентификатор панели задач.

Для установки из среды автоматизации: `.\scripts\install-local.ps1 -Installer .\dist\Planer-1.3.0-win-x64-setup.exe`. Скрипт запускает установщик в обычном интерактивном сеансе с минимальными правами через одноразовое задание и удаляет это задание после завершения. Это обеспечивает регистрацию обработчиков в реестре, который видит Windows; изолированное представление реестра инструментов не является проверкой установки для рабочего стола. При обычном ручном запуске достаточно открыть установщик.

Helvetica Neue (Roman, Bold и Light) и исходные иконки включены в приложение. Отдельно устанавливать шрифт в Windows не требуется. Мелкий текст использует небольшой межбуквенный интервал; при увеличении окна интерфейс масштабируется целиком.

Минимальные размеры окон: основной планер — 1100×720, отдельный день — 300×420 логических пикселей, с учётом DPI и доступной области монитора. При LayoutCycleException интерфейс восстанавливается из текущего состояния данных; повторные сбои показывают отдельную кнопку восстановления вместо закрытия приложения.

Рабочая база находится в `%LOCALAPPDATA%\Planer\planner.db`. Удаление приложения не удаляет базу. Для резервной копии закройте планер и скопируйте файл базы.

## Возможности

- Планеры недели, месяца и года; цели каждого периода и отдельные заметки недель/месяцев.
- Задачи по четырём приоритетам, создание/редактирование, выполнение, ПКМ-меню и перенос мышью.
- Повторы задач: неделя, две недели, месяц, год. Отдельное выполнение каждого вхождения, подтверждение удаления текущей/будущей части и выбор области переноса. История сохраняется.
- Образ карточки сохраняет точку захвата; зона прилипания — половина ширины дня по горизонтали и 20 пикселей по вертикали. Горизонтальное отлипание — при смещении курсора более чем на 60 пикселей от положения в момент прилипания.
- Общее хранилище нераспределённых задач. Незавершённые задачи прошедших недель возвращаются в него при смене недели/следующем запуске.
- Утро/день/вечер с перераспределением высоты от пустых секций; длинный текст раскрывается при наведении.
- Настроение и до трёх активных привычек с сохранением истории; завершение привычки требует подтверждения.
- Повторяющиеся платежи с включительной датой окончания и сохранением прошлого при изменении расписания.
- При удалении повторяющейся задачи можно выбрать одно вхождение или выбранное и будущие; прошлые отметки сохраняются.
- Шестерёнка → «Финансы»: один текущий план дохода и расходов, активные ежемесячные платежи, до семи категорий с лимитами, круговая диаграмма и остаток. Это планирование бюджета; ввод фактических расходов будет добавлен отдельно. Доход сохраняется по Enter или при выходе из поля.
- Платежи видны и на месяце; ПКМ по периоду открывает календарь со ссылками на год, месяц и неделю.
- Одно синхронизированное окно текущего дня поверх других окон.
- Значок области уведомлений: открыть планер, текущий день поверх окон, выход.
- Текущая серия привычки в списке и поздравления на 14, 30, 60 и 90 дней подряд.
- Утреннее напоминание при задачах сегодня: 10:00, при позднем включении — до 12:00 один раз за день. Сообщение о переносе — только после фактического перемещения задач недели. Клик открывает сегодняшний день/текущую неделю.
- Шестерёнка → «Автозапуск и уведомления»: раздельные переключатели. Автозапуск окна в области уведомлений по умолчанию выключен. Уведомления включены и работают также при закрытом приложении через короткое задание Windows в 10:00, понедельник 00:00 и при входе. Фоновое задание не требует прав администратора, не будит компьютер и учитывает пропущенный запуск. Удаление программы убирает её интеграцию Windows, база сохраняется.

## Сборка и проверки

Требуются Windows, .NET SDK 10 и доступ к NuGet. Версии зависимостей закреплены. Для установщика нужен Inno Setup 6.

```powershell
.\scripts\dotnet.ps1 build src/Planer.App/Planer.App.csproj /p:Platform=x64
.\scripts\dotnet.ps1 run --project tests/Planer.Tests/Planer.Tests.csproj
.\scripts\dotnet.ps1 run --project tests/Planer.Windows.Tests/Planer.Windows.Tests.csproj
.\scripts\build-installer.ps1
```

Сборка установщика выполняет тесты Core/SQLite и Windows-интеграции, затем проверяет 60 состояний опубликованного приложения: семь экранов, увеличенное окно, режимы года, многострочные заметки/описания, плюс, формы, образ перетаскивания, календарь и его переходы, будущие повторы, плановый бюджет и его диаграмму/лимиты/формы, жизненный цикл значка Shell и иконки обоих окон, скрытый автозапуск, переходы уведомлений, настройки, оформление выполненных дел, расположение/размеры кнопок, изменение размеров и путь восстановления обоих окон. При ошибке установщик не собирается. Отдельная проверка установки, запуска и удаления: `.\scripts\verify-installer.ps1`; она выполняется внутри новой папки `artifacts` и останавливается, если Планер уже установлен.

Проверка установленных иконок и ярлыков: `.\scripts\verify-shell-icons.ps1 -InstallDirectory "$env:LOCALAPPDATA\Programs\Planer"`. Она сверяет ICO, явный источник значка и AppUserModelID ярлыков меню «Пуск»/рабочего стола; необязательный `-OutputDirectory` сохраняет изображения, полученные от Windows Shell, для просмотра.

70 сценарных тестов проверяют смену недели, назначение прошедшим дням, матрицу, привычки и их серии, повторение задач/платежей, изменение цепочек, сохранение истории и календарных якорей, ошибки записи, миграцию старой SQLite, перезапуск, распределение высоты, геометрию прилипания, лимиты планового бюджета с копейками, семь цветов категорий, сохранение финансов при смене месяца и правила/дедупликацию уведомлений. Ещё 6 Windows-проверок используют временные идентификаторы, ярлыки, запись автозапуска, задание и тихие уведомления; проверяют настоящий COM-обработчик трёх переходов, реальную историю Windows и обновление старых пушей, затем удаляют свои регистрации. Личные данные и рабочие настройки не используются. Консольные runner возвращают ненулевой код при ошибке.

Клики по пушам используют прямой обработчик Windows, включая запуск закрытого планера. Интерактивная проверка установленного сервера: `.\scripts\verify-toast-activation.ps1 -OpenWindows` (добавьте `-ExpectCold`, если планер закрыт). Она вызывает тот же COM-интерфейс, что Windows при клике, и открывает сегодняшний день, привычки и текущую неделю в одном экземпляре. Запускать её следует по запросу пользователя, когда видимые окна не помешают работе или игре; автоматическая проверка интерфейса — verify-ui.ps1 с отдельными данными и окнами за пределами экрана.

Для рендеров всех экранов из отдельной тестовой базы:

```powershell
.\scripts\dotnet.ps1 build src/Planer.App/Planer.App.csproj --configuration Release /p:Platform=x64 /p:SelfContained=false
.\scripts\verify-ui.ps1
```

Изолированная демонстрация:

```powershell
& '.\src\Planer.App\bin\x64\Release\net10.0-windows10.0.26100.0\win-x64\Planer.App.exe' --data-dir "$PWD\artifacts\demo-data" --demo
```

`--demo` заполняет только новую явно указанную базу. Рабочие данные, сборки и кэши не попадают в Git.

## Структура

- `Planer.Core`: модели и правила, независимые от окон.
- `Planer.Data`: транзакционное SQLite-хранилище.
- `Planer.App`: WinUI-представления и команды MVVM.
- `Planer.Tests`: сценарные проверки.
- `docs/requirements.md`: согласованное поведение; `AGENTS.md`: исходный план и журнал.

Работа ведётся в `master`; функциональные этапы зафиксированы отдельными коммитами. Установщик не подписан сертификатом разработчика.
