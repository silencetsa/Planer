# Planer development rules

- Implement a native Windows planner using C#, .NET 10, WinUI 3, MVVM and SQLite.
- Preserve the pastel weekly layout and the agreed behavior documented in `docs/requirements.md`.
- Work on `master`. One independently reviewable feature per commit.
- Update `AGENTS.md` with completed work, validation, decisions and material blockers at each feature commit.
- Keep domain logic in Planer.Core, SQLite persistence in Planer.Data, presentation in Planer.App. Code-behind may implement view-only input, dialogs, drag/drop and window lifecycle; business rules belong to services and view models.
- Never commit the user's database, credentials, signing keys, caches or build output.
- Run meaningful tests for rollover, habit history, payment recurrence and historical preservation; build the Windows application and verify its rendered UI before delivery.
- No parallel agents are requested. Implement in this chat.
- Keep QA offscreen with an explicitly isolated database. Do not launch or activate the installed planner or its topmost day window for testing unless the user explicitly requests live testing; these windows interrupt games. Ordinary launch opens the main planner; the separate day requires an explicit action (day arrow, tray command or click on a morning notification).

## Устойчивые размеры и восстановление LayoutCycleException
- В рабочем crash.log подтверждён LayoutCycleException от 16 октября 00:42. Убраны два источника обратной связи: изменение размеров поверхности из SizeChanged и повторное Measure из Arrange секций дня. Масштаб рассчитывается по ограничению родителя; перенос карточек по-прежнему учитывает RenderTransform.
- Естественная высота определяется по содержимому секции, а ScrollViewer получает конечную высоту. Полоса прокрутки не меняет ширину текста при переполнении; прокрутка и заимствование свободной высоты сохраняются. Повторная установка того же состояния плюса не запускает лишнее измерение.
- PreferredMinimumWidth/Height ограничивают основное окно до 1100×720, день до 300×420 логических пикселей. Учтены DPI, переход между мониторами и меньшая рабочая область; для очень маленьких областей предусмотрено равномерное уменьшение интерфейса.
- Глобальный обработчик регистрируется до создания окон, пишет исходное сообщение XAML и Exception, обрабатывает только LayoutCycleException или точную диагностику «Layout cycle detected». После выхода из текущего прохода UI пересоздаёт оба представления из того же ViewModel, закрывая открытые формы через Hide без подтверждения их действий. После третьего последовательного сбоя вместо повторного перестроения появляется простая кнопка восстановления.

## Автозапуск, Windows Toast и фоновое расписание
- В шестерёнке добавлена форма «Автозапуск и уведомления» в общем стиле. Переключатели независимы: автозапуск по умолчанию выключен, уведомления включены. Ошибка сохранения внешних настроек/SQLite отменяет форму и восстанавливает предыдущие настройки.
- Автозапуск хранится только в HKCU Run и запускает установленный EXE с --startup. Главное окно остаётся скрытым, значок/меню работают; при недоступной области уведомлений окно показывается как запасной путь. Закрытие главного окна по-прежнему завершает приложение.
- Для уведомлений закрытого приложения создано собственное задание текущего пользователя: ежедневно 10:00, понедельник 00:00 и вход с задержкой 15 секунд. InteractiveToken/LeastPrivilege, без пароля/администратора, без пробуждения ПК и ограничения на батарее; StartWhenAvailable и ограниченные повторы при ошибке. --notification-check не создаёт окно, при работающем планере передаёт проверку через current-user pipe.
- Toast использует Windows.UI.Notifications, зарегистрированный AUMID/ярлык со stub CLSID и собственный протокол. Протокол разрешает только today/week/habits без путей/параметров; режим --protocol отклоняет дополнительные аргументы. Однобайтовый IPC принимает только четыре фиксированные команды и ограничен тем же пользователем. Окно сегодняшнего дня остаётся единственным, неделя открывается на сегодняшней дате.
- Доставка сохраняет подтверждение после принятия Windows; наличие того же тега в истории предотвращает повторный баннер после сбоя записи. Отключённые уведомления Windows не обходятся. Для нового AUMID getter Setting может вернуть 80070490 до первого принятого toast; этот узкий случай допускает Show, что подтверждено реальной историей Windows.
- Установщик регистрирует протокол и уведомления и настраивает фоновое задание. Удаление убирает только собственное задание/автозапуск/историю/регистрацию, не SQLite. Нативные рендеры и демо-запуски из альтернативной БД отключают рабочую интеграцию.
- Добавлен Planer.Windows.Tests: 5 проверок протокола/XML-экранирования, IPC, временного автозапуска, реального задания и тихого toast с историей/дедупликацией. Временные идентификаторы и регистрации удаляются. Уточнено отображение HRESULT отсутствующего задания: .NET проецирует его как FileNotFoundException, поэтому проверяется сам код; стандартный LeastPrivilege может отсутствовать в XML и проверяется через фактическое свойство Principal.
- Сборки WinUI прошли без предупреждений. Дополнительно проверены фоновый запуск без окна и переходы через уже работающий экземпляр; нативный сценарий скрытого старта подтверждает значок при невидимом главном окне и открытие через меню.
- Источники: https://learn.microsoft.com/en-us/windows/win32/shell/enable-desktop-toast-with-appusermodelid , https://learn.microsoft.com/ru-ru/windows/apps/design/shell/tiles-and-notifications/toast-desktop-apps , https://learn.microsoft.com/en-us/windows/win32/taskschd/daily-trigger-example--scripting- , https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys .
